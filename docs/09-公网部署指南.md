# 09 · 公网部署指南（阿里云轻量应用服务器）

> 目标：满足参赛要求第 5 条 —— **作品具备公网内的联通性，评审可通过公网访问并能流畅运行**。
> 本应用是**单端口**架构（Node 后端同时托管前端静态资源），部署后评审直接访问 `http://公网IP:3000` 即可，不需要数据库、不需要额外中间件。

---

## 一、先看这三件事（决定你走哪条路）

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **用 IP + 端口访问不需要 ICP 备案** | 默认用 `http://公网IP:3000`。若改用域名走 `80/443`，中国大陆节点的服务器**必须完成 ICP 备案**，否则会被云厂商拦截 |
| 2 | **阿里云轻量服务器的防火墙在「控制台」，不在系统里** | 控制台默认只放行 22/80/443/3389。**不手动放行 3000，公网一定打不开**（系统内 `ufw` 不是主因，但脚本也会一并处理） |
| 3 | ⚠️ **校园大模型网关公网不可达** | `myai.bupt.edu.cn` 解析链为 `→ vn.bupt.edu.cn → 10.3.19.2`，是**内网私有地址**（公网 DNS 查询结果一致）。部署到阿里云后调用必然失败。系统会**自动降级为离线模板模式**（功能完整、不会报错），但要展示真实大模型能力，需换成公网 API —— 见第七节 |

---

## 二、三种常驻方式，选哪个

| 方式 | 一句话 | 适合谁 | 开机自启 |
| --- | --- | --- | --- |
| **PM2**（推荐） | `npm i -g pm2` 后一条命令起停，`pm2 logs` 看日志最直观 | 不熟悉运维、想快速看到效果 | `pm2 save` + `pm2 startup` |
| systemd | 系统原生服务，无需额外依赖，可做安全加固 | 想要规范化、长期稳定运行 | `systemctl enable` |
| Docker Compose | 环境最一致，换机器一键复现 | 熟悉 Docker / 用宝塔或 Docker 应用镜像 | `restart: unless-stopped` |

> 三种方式的配置**都已经给你准备好了**：`ecosystem.config.js`（PM2）、`deploy/heritage-travel.service`（systemd）、`Dockerfile` + `docker-compose.yml`（Docker）。下面以 **PM2** 为主路径。

## 三、部署步骤（PM2 路径）

### 步骤 1 · 确认服务器信息

在阿里云控制台记录两样东西：

- **公网 IP**（实例详情页可见）
- **登录方式**：轻量服务器默认用**密钥对**或**管理员密码**，用户名通常是 `root`（Ubuntu 镜像也可能是 `ubuntu`，用 `sudo`）

> 建议规格：**2 核 2G / 3M 带宽** 已足够。本应用只有一个依赖（express），内存占用约 60–80 MB。

---

### 步骤 2 · 把代码放到服务器上

**方式 A：从 GitHub 拉取（推荐，后续更新只需 `git pull`）**

先在**你的电脑上**把改动提交并推送（`server/.env` 已被 `.gitignore` 忽略，**不会**被推上去，密钥不会泄露）：

```powershell
cd e:\workfile\feiyi-banyou
git add -A
git commit -m "feat: 接入大模型 + 公网部署配置"
git push origin main
```

然后 **SSH 登录服务器**，拉取代码：

```bash
# 大陆服务器访问 github.com 常常很慢，用加速镜像更稳
git clone https://ghfast.top/https://github.com/G-xl23/feiyi-banyou.git
cd feiyi-banyou
```

**方式 B：直接上传（不走 GitHub）**

在你电脑的 PowerShell 里执行（把 IP 换成你的）：

```powershell
cd e:\workfile\feiyi-banyou
# 先打包，排除依赖目录（否则会很慢）
git archive --format=tar -o ..\feiyi-src.tar HEAD
scp ..\feiyi-src.tar root@你的公网IP:/root/
```

> 注意：`git archive` 只包含**已提交**的内容，请先 `git commit`。若不想提交，改用：
> `tar --exclude=node_modules --exclude=.git --exclude=logs -czf ..\feiyi-src.tar.gz .`（Windows 10+ 自带 `tar`）

服务器上解包：

```bash
mkdir -p /root/feiyi-banyou && tar -xf /root/feiyi-src.tar -C /root/feiyi-banyou
cd /root/feiyi-banyou
```

---

### 步骤 3 · 一键部署

在服务器上、**项目根目录**执行：

```bash
sudo bash deploy/deploy.sh
```

脚本会自动完成：装 Node 20 → 建运行目录 `/opt/feiyi-banyou` → 拷贝代码装依赖 → 生成 `server/.env` → 放行 `ufw` 端口 → PM2 启动并配置开机自启 → 本机自检。

常用变体：

```bash
sudo PORT=8080 bash deploy/deploy.sh        # 换端口（比如 3000 被占用）
sudo bash deploy/deploy.sh --systemd        # 改用 systemd
sudo bash deploy/deploy.sh --docker         # 改用 Docker Compose
```

> 如果脚本是从 Windows 拷过去的、报 `bad interpreter` 或 `\r` 相关错误，先转换换行符：
> `sed -i 's/\r$//' deploy/deploy.sh`

---

### 步骤 4 · 控制台放行防火墙（**最容易漏、漏了必然打不开**）

1. 打开 [轻量应用服务器控制台](https://swas.console.aliyun.com/) → 点击你的实例
2. 左侧选 **「防火墙」** 标签页
3. 点 **「添加规则」**，按下面填：

| 字段 | 填写 |
| --- | --- |
| 应用类型 | 自定义 |
| 协议 | TCP |
| 端口范围 | `3000`（或你在步骤 3 里自定义的端口） |
| 备注 | 非遗伴游 Web 服务 |
| 来源 | `0.0.0.0/0`（所有 IPv4） |

4. 保存。规则**立即生效**，无需重启服务器。

> 若选择用 Nginx 反代走 80 端口，则放行 `80`（域名需已备案）。

### 步骤 5 · 验证

| # | 检查项 | 怎么验证 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 服务在本机活着 | 服务器上执行 `curl -s localhost:3000/api/ready` | 返回 JSON，含 `"ok":true` |
| 2 | 公网能打开 | 浏览器访问 `http://公网IP:3000` | 出现「非遗伴游」界面 |
| 3 | 状态栏正常 | 看页面右上角胶囊 | `系统就绪 · 知识库 3 城 / 23 区县 · 非遗 39 项 · 8 个智能体 · 离线模板模式`（或「大模型在线（模型名）」） |
| 4 | 业务功能可用 | 点「智能对话」输入 `介绍一下广济桥` | 下方「多智能体协作链路」实时逐条点亮，最后出结果 |
| 5 | 长连接（SSE）没被缓冲 | 观察第 4 步 | 步骤是**逐条实时出现**，不是最后一次性蹦出来 |
| 6 | 手机也能开 | 用手机流量（非校园网）访问同一地址 | 同样正常 —— 这条最能证明"公网可达" |

> **建议用手机 4G/5G 流量验证一次**：手机不在校园网里，如果手机能打开，就说明作品确实满足"公网内联通"的要求。

## 四、常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 浏览器一直转圈 / 连接超时 | 阿里云**控制台防火墙**没放行端口 | 回到步骤 4 添加 TCP 规则 |
| 服务器上 `curl localhost:3000` 通，但公网不通 | 同上（系统防火墙与云防火墙是两件事） | 同上 |
| 报 `EADDRINUSE` | 3000 端口被占用 | `sudo ss -lntp \| grep 3000` 查占用者，或换端口重新部署 |
| 页面能打开，但对话/规划一直无响应 | 后端异常或大模型超时 | `pm2 logs feiyi-banyou`（或 `journalctl -u feiyi-banyou -f`）看报错 |
| 协作链路最后一次性出现（不实时） | 中间套了 Nginx 且没关缓冲 | 用 `deploy/nginx-feiyi-banyou.conf`（已含 `proxy_buffering off`） |
| 重启服务器后网站打不开 | 没配置开机自启 | `pm2 save && pm2 startup`；systemd 方式用 `systemctl enable feiyi-banyou` |
| `node: command not found` | Node 未安装或不在 PATH | 重跑 `sudo bash deploy/deploy.sh`，脚本会自动装 Node 20 |
| Docker 方式拉镜像很慢/失败 | 大陆拉 Docker Hub 受限 | 配置镜像加速器，或直接用 PM2 方式（无需拉镜像） |
| 站点显示「大模型不可用」 | 密钥错 / 网关公网不可达 | 见第七节，换公网 API |

## 五、关于「离线模板模式」

**这不是故障，是本项目的设计特性。** 未配置大模型密钥时：

- 页面状态栏显示 `离线模板模式`，所有功能（行程规划、讲解、美食、知识库、AIGC、产业赋能、看板）**全部可用**；
- 内容由内置模板引擎基于本地知识库生成，事实准确、不做编造；
- 一旦填入有效密钥并重启，状态栏自动变为 `大模型在线（模型名）`，讲解稿 / 文创 / 知识问答即由大模型生成。

所以**先按本指南部署上线、保证公网可访问，再决定是否接公网大模型**，是完全可以的顺序。

## 七、后续接入公网大模型（三行配置）

校园网关公网不可达，公网部署请改用**公网可访问的 OpenAI 兼容接口**。既然是阿里云服务器，**推荐阿里云百炼（通义千问）**：同地域内网调用、延迟低，新用户有免费额度。

1. 到 [阿里云百炼控制台](https://bailian.console.aliyun.com/) 开通并创建 **API-KEY**（形如 `sk-xxxxxxxx`）
2. 编辑服务器上的配置文件：

```bash
sudo nano /opt/feiyi-banyou/server/.env
```

把大模型三行改成（其余不动）：

```ini
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=sk-你的百炼密钥
LLM_MODEL=qwen-plus
LLM_TIMEOUT_MS=60000
```

3. 重启服务：

```bash
pm2 restart feiyi-banyou        # Docker 方式：docker compose restart
```

4. 验证：看启动日志有没有 `大模型连通性自检通过`，或直接看页面右上角是否变成「大模型在线（qwen-plus）」。

**任何 OpenAI 兼容服务都能这么换**，只改这三行、代码零改动：

| 服务 | LLM_BASE_URL | LLM_MODEL |
| --- | --- | --- |
| 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| DeepSeek 官方 | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

> **推理型模型注意**：若模型响应里带 `reasoning_content`，或日志出现 `finish_reason=length` 且正文为空，说明它把 token 预算花在了思考链上。在 `.env` 里加一行 `LLM_DISABLE_THINKING=true` 即可（已在北邮网关 `deepseek-v4-flash` 上实测有效）。
> 想快速体检就用项目自带的自检脚本：`node scripts/check-llm.js`。

## 八、可选的 Nginx 反向代理

只有想用 `http://域名` 或 `http://IP`（不带 `:3000`）访问时才需要。配置文件已备好：`deploy/nginx-feiyi-banyou.conf`。

```bash
sudo apt install -y nginx
sudo cp deploy/nginx-feiyi-banyou.conf /etc/nginx/sites-available/feiyi-banyou
sudo ln -sf /etc/nginx/sites-available/feiyi-banyou /etc/nginx/sites-enabled/feiyi-banyou
sudo nginx -t && sudo systemctl reload nginx
```

该配置已专门处理两件事：

- **SSE 不被缓冲**（`proxy_buffering off`）—— 否则「多智能体协作链路」的实时效果会消失；
- **超时给足 300s** —— 大模型单次调用可能十几秒，Nginx 默认 60s 会把请求掐断。

配 HTTPS（需域名已备案）：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## 九、安全与参赛提交注意

- 🔑 **密钥只放在 `server/.env`**，该文件已被 `.gitignore` 忽略；`Dockerfile` 与镜像里都不含 `.env`（见 `.dockerignore`）。
- 📦 **提交参赛材料时不要打包 `server/.env`**，只提交 `.env.example`。
- 🔒 阿里云防火墙按最小必要放行：只开你实际使用的端口（如 3000 或 80/443），不要图省事开全部端口。
- 👤 追求更规范的话用 systemd 方式，它以专用系统用户 `heritage` 运行并启用了 `NoNewPrivileges` / `ProtectSystem` 等加固项。
- 🎬 **演示视频建议**：在校园网内本地跑（可连校园网关展示真实大模型生成），或先按第七节给公网版接上百炼后再录，两条路都行。
