# 新增城市扩展指南（数据驱动扩展，零业务代码改动）

> 本系统采用"数据驱动"的多城市架构：**新增一个城市不需要修改任何 Agent、路由或前端代码**，只需在 `server/src/data/` 下追加 4 张数据表并跑一次自检。苏州（v3.0）即按本指南从零接入，可作为参照模板。

## 一、扩展总览

| 步骤 | 文件 | 做什么 | 是否必填 |
| --- | --- | --- | --- |
| 1 | `server/src/data/heritage.js` | 城市主体：非遗 / 景点 / 美食 / 民俗 | 必填 |
| 2 | `server/src/data/rural.js` | 乡村层级：统计 / 点位 / 工坊 / 好物 / 农事 / 村宿 | 必填（产业赋能与看板依赖） |
| 3 | `server/src/data/regions.js` | 区县列表 + 非遗归属区县映射 | 必填（下钻依赖） |
| 4 | `server/src/data/cities.meta.js` | 省份 + 别名（古称/地标/区县/物产） | 必填（城市识别依赖） |
| 5 | `node scripts/validate-data.js` | 数据完整性与别名识别自检 | 必跑 |
| 6 | 重启服务 | `npm start` | 必做 |

完成后自动生效的范围：8 个 Agent、前端全部下拉与联动、行程/讲解/美食/知识库/AIGC、乡村产业赋能、乡村振兴看板（含城市→区县下钻）、政务产业助手（问答/归纳/跨城市对比）、协作链路 SSE、演示模式参数（`?city=xxx`）。

## 二、各数据表填写规范

### 1. heritage.js —— 城市对象

```js
cities.nanjing = {
  id: 'nanjing',                 // 城市英文 id（唯一，小写）
  name: '南京',
  tagline: '六朝古都 · 金陵文脉',
  intro: '一句话城市与非遗定位（用于前端展示）',
  heritages: [ /* 见 1.1 */ ],
  attractions: [ /* 见 1.2 */ ],
  foods: [ /* 见 1.3 */ ],
  customs: [ /* 见 1.4 */ ]
};
```

**1.1 heritages[]（非遗项目）**

```js
{
  id: 'nj-yunjin',               // 项目 id（唯一，前缀用城市缩写）
  name: '南京云锦织造技艺',
  aliases: ['云锦', '南京云锦'],  // 别名参与知识库匹配与城市识别
  category: '传统技艺',           // 传统音乐/传统戏剧/传统技艺/传统美术/民俗/曲艺…
  level: '人类非遗',              // 人类非遗 | 国家级 | 省级 | 其他（如实标注）
  summary: '事实性简介（年代、工艺要点，均需可溯源）',
  masters: [ { name: '传承人姓名', title: '国家级代表性传承人' } ], // 无法核实时用 [{ name: '待核实', title: '以中国非遗网官方名录为准' }]
  experienceSpots: [ { name: '体验点名称', address: '详细地址', openTime: '以现场公告为准' } ]
}
```

> 硬性要求：`level` 必须与官方名录一致；不确定的批次年份不要写；每条数据在《非遗数据来源说明》文档中登记来源。

**1.2 attractions[]（景点）**

```js
{
  id: 'nj-zhonghuamen', name: '中华门（中华门瓮城）',
  type: '历史古迹', area: '秦淮区', durationMin: 90,
  desc: '景点历史（事实性）',
  heritageRefs: ['nj-yunjin']    // ★ 景点↔非遗关联：行程嵌入与讲解的匹配依据
}
```

> `heritageRefs` 是本系统"行程与非遗深度绑定"的核心，请按景点真实存在的非遗展示/体验关系填写，宁少勿错。

**1.3 foods[]（美食）**：`{ name, desc, heritageNote }`——`heritageNote` 关联饮食类非遗或民俗背景。

**1.4 customs[]（民俗）**：`{ name, desc }`。

### 2. rural.js —— 乡村层级

```js
rural.nanjing = {
  intro: '一句话乡村文旅定位',
  stats: [                       // 公开统计（看板统计卡）
    { label: '2024年乡村旅游接待', value: 'XX万人次', source: '来源（媒体/政府公开报道）与年份' }
  ],
  spots: [                       // 乡村点位（行程乡村模式/看板）
    { id: 'nj-huanglongxian', name: '黄龙岘茶文化村', village: '黄龙岘', county: '江宁区',
      type: '茶旅', durationMin: 150, bestSeason: '春季',
      desc: '…', highlights: ['…'],
      heritageRefs: ['nj-yunjin'], source: '来源' }
  ],
  workshops: [                   // 非遗工坊（产业赋能六件套的数据基础）
    { id: 'nj-yunjin-fang', name: '云锦工坊', heritageId: 'nj-yunjin',
      craft: '织造', scale: '…',
      products: [ { name: '云锦围巾', priceRange: [380, 1280], note: '…' } ],
      experience: { available: true, price: 100, durationMin: 60, desc: '…' },
      channels: ['电商', '体验零售'],
      painPoints: ['产品同质化', '线上内容能力弱'],   // 从 12 条痛点词表中选取
      source: '来源' }
  ],
  products: [                    // 乡村好物（增收测算的好物客单价来源）
    { name: '云锦书签', category: '织造', origin: '…',
      priceRange: [39, 129], heritageNote: '…',
      sellingPoints: ['…'], costRef: '行业通用参考', source: '来源' }
  ],
  farm: [ { name: '…', village: '…', season: '…', durationMin: 90, price: 80, desc: '…' } ],
  stays: [ { name: '…', village: '…', priceRange: [200, 500], desc: '…' } ]
};
```

> 建议规模（与现有三城对齐）：非遗 10 项以上、乡村点位 10 处以上、工坊 6 家左右、好物 6 种、农事 3 项、村宿 2-4 处、stats 6-8 条。

### 3. regions.js —— 区县归属（下钻口径）

```js
regions.nanjing = {
  counties: ['玄武区', '秦淮区', '鼓楼区', '栖霞区', '江宁区', '溧水区', '高淳区' /* 现行区划 */],
  heritage: {                    // 非遗项目 id → 归属区县（单归属，按代表性传承地）
    'nj-yunjin': '建邺区', 'nj-yuqincha': '江宁区'
  }
};
```

> 看板/对话体的区县过滤完全依赖此映射。个别跨区县项目按代表性传承地单归属；未映射的项目不参与区县级统计，但保留在全市口径中。

### 4. cities.meta.js —— 城市识别别名

```js
meta.nanjing = {
  province: '江苏省',
  aliases: ['金陵', '六朝古都', '夫子庙', '秦淮', '江宁', '盐水鸭', '云锦', '梧桐']
};
```

> 别名用于调度器从自然语言中识别城市（**最长别名优先**），以及"南京和苏州比怎么样"这类跨城市对比。`registry.detectCity` 会自动把区县名（含去掉"市/区/县"后缀的短名）注册为别名，无需重复填写。

## 三、自检与验收

```bash
cd server
node ../scripts/validate-data.js   # ① 数据完整性与别名识别自检
npm start                          # ② 重启服务
node ../scripts/smoke-test.js      # ③ 42 项端到端冒烟（自动覆盖新城市的基础链路）
```

自检覆盖：城市 id 唯一性、四张表齐全、heritageRefs 引用有效、区县映射无悬空、别名不与其他城市冲突、`detectCity` 能通过别名/区县名识别新城市。

**人工验收清单**：

- [ ] `GET /api/ready` 的 `knowledgeCities` 包含新城市，`knowledgeCounties` 数量增加
- [ ] `GET /api/cities` 返回新城市及规模；前端下拉出现新城市且联动正常
- [ ] `GET /api/insight?cityId=新城市` 与 `?county=某区县` 均返回正确口径（非法区县返回 400 并提示已收录清单）
- [ ] 工作人员对话体问"帮我总结一下新城市的非遗与产业情况"，回答口径为新城市
- [ ] 问"新城市和苏州比怎么样"，进入跨城市对比

## 四、设计原理（为什么零代码改动）

1. **统一注册中心 `registry.js`**：所有 Agent 与路由不直接读城市字典，而是经 `registry` 的 `cityIds / assertCity / counties / detectCity` 访问；新增城市只是注册中心多了一个键，校验、识别、列表全部自动覆盖。
2. **数据驱动路由**：调度器不维护"城市→关键词"映射，城市识别走 `detectCity`（别名最长优先）；景点名匹配遍历 `db.cities` 全部城市——新增城市自动进入识别范围。
3. **算法与数据分离**：HLI 指数、评分函数、增收测算、定价三档全部是通用算法，输入来自数据表；知识库检索打分同理。
4. **前端按元信息渲染**：下拉、区县联动、看板口径选择器、演示模式参数全部读 `/api/cities` 与 `/api/regions`，新增城市零改动。

## 五、常见问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 问句提到新城市但被当成默认城市 | `cities.meta.js` 别名不足 | 补充古称/地标/区县/物产别名，重跑 validate-data |
| 看板切到某区县后统计为空 | 该区县无非遗归属映射或无乡村点位 | 属正常"口径回落"，结论会显式标注；如需数据，补 `regions.heritage` 映射与 rural 数据 |
| 工坊赋能页没有新城市工坊 | `rural.workshops` 未填或 `heritageId` 悬空 | 检查 heritageId 与 heritage.js 中项目 id 一致 |
| 冒烟测试某城市断言失败 | 数据规模低于断言阈值（如非遗 <10 项） | 按"建议规模"补齐数据 |
| PDF/文档中的城市数未更新 | 文档为静态交付物 | 按新城市数据更新《01 设计文档》《02 作品简介》《04 数据来源说明》中的收录规模表 |

## 六、数据合规提醒

- 全部事实性数据（级别、批次、传承人、地址、统计数字）必须来自官方公开渠道并在《非遗数据来源说明》登记；**禁止用大模型生成事实数据**。
- 价格区间标注"市场公开常见区间，非官方指导价"；成本结构标注"行业通用参考"。
- 开放时间统一"以现场公告为准"；不确定的传承人以"待核实 + 官方名录为准"占位。
