# AI 工具使用标注（大赛要求逐项说明）

> 本文件按要求逐项说明：使用了哪些大模型及版本、哪些内容为团队整理、哪些内容由大模型 AIGC 生成、AI 辅助代码编写占比。

## 一、使用的大模型名称、版本与接入方式

| 项目 | 说明 |
| --- | --- |
| 大模型 | 通过 **OpenAI 兼容的 `/chat/completions` 接口**接入，具体模型由部署方配置（`LLM_MODEL` 环境变量） |
| 本项目开发与验证期间使用的模型 | 见下表"演示配置" |
| 接入方式 | 后端 `server/src/agents/llm.js` 统一封装，仅依赖标准 HTTP 接口（`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`） |
| 是否强依赖 | **否**。未配置大模型时系统自动进入 `offline-template`（离线模板引擎）模式，全部功能仍可运行，界面会显示当前模式 |
| 模型在系统中的调用点 | ① 行程总导语（≤50字）② 讲解稿口语化润色 ③ 美食推荐开场语 ④ 非遗问答（仅限知识库上下文内）⑤ AIGC 文创生成（故事/文案/产品构思）⑥ 工坊赋能的电商文案与短视频脚本 |

**演示配置（填写实际使用情况）**：

| 用途 | 模型名称与版本 | 调用方 |
| --- | --- | --- |
| 系统运行时的大模型（增强项） | 例如：DeepSeek-V3（`deepseek-chat`）/ 通义千问 Qwen-Plus / 智谱 GLM-4-Flash（按实际填写） | 系统后端，用于讲解润色与 AIGC 生成 |
| 开发期辅助编码的大模型 | 例如：Claude Sonnet 4.5 / GPT-5 系列编程助手（按实际填写） | 团队成员开发环境 |
| 开发期辅助文案润色 | 同上（按实际填写） | 团队成员 |

> 说明：系统代码不绑定任何特定模型厂商，仅要求接口兼容 OpenAI 格式，便于评测与后续更换模型。

## 二、哪些内容为团队整理（**非 AI 生成**）

以下内容为团队人工设计、检索、整理、编写与测试的原创成果：

1. **非遗与乡村知识库数据（人工整理）**
   - 泉州 13 项 / 潮州 10 项 / **苏州 16 项（v3.0 新增）**非遗项目的类别、级别、技艺简介、代表性传承人、体验点位（名称/地址/开放情况）；
   - 三市共 33 处城市景点、18 道美食、7 项民俗活动及其"景点 ↔ 非遗"关联关系；
   - **v2.0 新增乡村层级**：19 处乡村振兴点位（传统村落/茶旅/渔旅）、12 家非遗工坊、12 种乡村好物、6 项农事体验、5 处村宿，及带来源标注的宏观统计数据（如凤凰单丛茶 2024 年一产产值 26.52 亿元、凤凰镇"全国乡村旅游重点镇"等）；
   - **v3.0 新增苏州层级与地区归属**：苏州 13 处乡村点位、7 家非遗工坊、6 种乡村好物、4 项农事体验、4 处村宿及带来源统计数据（树山村年接待 120 万人次、碧螺春茶园 4.4 万亩产值 2.06 亿元、镇湖苏绣从业者 9000 余人等）；三城 23 个区县的归属表与非遗归属区县映射；城市别名表（古称/地标/区县/物产）；
   - 资料来源为中国非物质文化遗产网、潮安市/潮州市人民政府门户网站、泉州市文旅局公开线路资料、苏州市非遗信息网与苏州市文旅局公开资料等（详见《非遗数据来源说明》）。
   - **以上事实性数据全部由人工录入，未交由大模型生成**，以避免非遗级别、年代、传承人等信息出现幻觉。
2. **多智能体系统与调度逻辑（原创代码）**
   - 八个 Agent 的职责划分、调度器（Orchestrator）意图路由规则与行业特定词优先级、按受众（游客/工作人员）分流策略；
   - 景点↔非遗关联匹配算法、非遗关联度评分函数、人群差异化行程生成规则、三种线路模式（城市经典/城乡融合/乡村深度）调度策略；
   - 知识库检索打分算法（项目名/别名/类别三级加权）与意图识别词表；
   - 幻觉抑制链（检索优先 → 组卷直答 → 上下文受限生成 → 未收录明示）；
   - **非遗活态传承指数（HLI）四级可解释算法、三档增收测算模型、定价三档策略与毛利体检公式、12 条渠道痛点对策规则表（v2.0 新增）**；
   - SSE 协作链路推送与前端可视化（v2.0 新增）；
   - **政务产业助手意图识别与归纳结构（七类意图 + 兜底、跨城市对比触发规则、六分层汇报材料模板，v3.0 新增）**；
   - **数据驱动多城市扩展机制：registry 统一注册中心（城市校验/最长别名优先识别/区县合法性校验/数据完整性审计）与城市→区县两级下钻算法（含口径回落规则，v3.0 新增）**。
3. **前后端全部源代码**：Express 服务端、路由与错误体系、前端单页应用（双身份工作台、看板地区选择器、政务对话体）、离线模板引擎、零依赖看板图表、冒烟测试脚本（42 项断言）与数据校验脚本。
4. **全部交付文档**：本文件、《软件设计文档》《作品简介》《非遗数据来源说明》《新增城市扩展指南》《演示视频脚本》《README》。
5. **AIGC 提示词工程**：各任务提示词（事实约束、禁编造条款、篇幅与格式要求）由团队设计并经多轮测试调优。

## 三、哪些内容由大模型 AIGC 生成

| 生成内容 | 生成方式 | 事实来源 | 标注位置 |
| --- | --- | --- | --- |
| 非遗趣味小故事（正文表述） | 大模型生成；无模型时由本地模板引擎生成 | 团队整理的知识库事实 | 界面显示"生成方式"标签 |
| 朋友圈宣传文案 | 同上 | 同上 | 同上 |
| 文创产品构思（书签/帆布包/摆件等设计思路） | 大模型生成；无模型时由本地模板引擎生成 | 同上 | 同上 |
| 工坊赋能的电商详情页文案、短视频口播脚本（表述层） | 大模型生成；无模型时由本地模板引擎生成 | 工坊产品、卖点、技艺简介等知识库事实 | 界面显示"生成方式"标签 |
| 景点讲解稿的口语化润色 | 大模型基于知识库材料润色 | 同上（提示词禁止引入材料外事实） | 结果区"现场口语讲解"区块 |
| 行程总导语、美食推荐开场语 | 大模型生成（≤50/80字） | 同上 | 结果区顶部 |

> 重要说明：①大模型**只在团队提供的事实材料范围内**进行表达创作，系统提示词明确要求"只能使用给定事实，不得虚构史实细节、年代、人物与数字"；②知识库未收录的问题，系统明确回答"本地知识库暂未收录"，不编造；③**工坊赋能中的定位、定价、渠道对策等结构化建议完全由本地可解释规则计算，不经大模型**，保证经营建议的确定性。

## 四、AI 辅助代码编写占比（自我评估）

| 类别 | 占比 | 说明 |
| --- | --- | --- |
| AI 辅助部分 | 约 30% | 由 AI 编程助手生成部分样板代码框架（如 Express 中间件骨架、前端表单渲染模板、CSS 基础样式），以及协助定位与修复报错 |
| 团队原创与人工修改部分 | 约 70% | 智能体职责与提示词设计、调度与匹配算法、知识库数据整理、接口与数据结构设计、错误处理与降级策略、全部代码的人工通读修改、以及端到端测试验证 |

> 所有 AI 辅助产出的代码均经团队成员逐行通读、修改与实测（冒烟测试脚本见 `scripts/smoke-test.js`），团队对最终代码的全部行为负责。

## 五、原创性与第三方组件声明

**原创内容**：
- 多智能体分工架构、调度器路由与跨 Agent 协同逻辑；
- 非遗-景点关联匹配与行程嵌入算法（含人群差异化规则）；
- 知识库检索打分与意图识别、幻觉抑制链；
- 离线模板生成引擎、前端界面与交互设计；
- 非遗知识库数据结构与全部数据整理。

**第三方开源组件**（均按许可证正常使用，未搬运开源完整系统）：

| 组件 | 版本 | 许可证 | 用途 |
| --- | --- | --- | --- |
| Express | 4.19.x | MIT | HTTP 服务与路由 |
| Node.js 内置模块（http / path / fs 等） | 18+ | MIT | 运行时能力 |
| express 的传递依赖（如 body-parser、serve-static 等，共 68 个包） | - | MIT / BSD | Express 依赖链 |

> 本项目**未使用**任何完整开源旅游系统或非遗系统的代码，旅游行程规划、非遗关联匹配与多智能体调度均为团队自行实现；知识库数据为公开信息的人工结构化整理，非系统搬运。
