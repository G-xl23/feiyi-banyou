## 一、需求分析

### 1.1 项目背景

地方文旅与非物质文化遗产（以下简称"非遗"）长期存在"两个孤立系统"的问题：

1. **游客侧**：主流行程规划工具只解决"去哪玩、住哪里、怎么走"，输出的行程与本地非遗资源完全脱节。游客到了景区，往往只看到建筑与风景，看不到背后的手艺与民俗，体验停留在"拍照打卡"层面。
2. **非遗侧**：非遗项目的数字化保护大多停在静态名录与展馆陈列，传承人、技艺、体验点位信息分散在文旅部门公告与地方公众号中，缺少面向普通游客的"可理解、可到达、可体验"的导览通道。
3. **内容侧**：非遗宣传内容生产能力薄弱，基层文旅单位缺乏低成本产出非遗故事与文创构思文案的工具。

本项目将"文旅导览多智能体"与"非遗知识保护智能体"两条选题融合，用大模型与多智能体（Agent）技术构建一套面向普通游客的导览助手：**旅行行程深度嵌入本地非遗资源，既会规划旅行，又会讲解非遗、回答非遗咨询、生成非遗文创内容**，实现"游地方、知非遗"。

### 1.1.1 从"导览助手"到"三端赋能平台"的升级（v2.0）

在导览场景之上，我们进一步观察到乡村非遗的深层矛盾：

4. **产业侧（工坊/传承人）**：乡村非遗工坊普遍面临"手艺好、卖不好"的困境——产品同质化、定价缺依据、电商文案与短视频内容能力弱、体验客流无法转化为产品订单。非遗要活态传承，必须先"能造血"。
5. **治理侧（政府/乡镇）**：基层文旅部门掌握的非遗数据分散，缺少低成本、可解释的量化工具来判断"哪个项目该重点扶持、投入能带来多少增收"。

因此系统升级为**三端闭环平台**：

- **游客端**（原有五大 Agent）：游地方、知非遗；
- **工坊端**（新增乡村产业赋能 Agent）：一键生成产品定位、三档定价、电商详情页文案、短视频脚本、包装升级与渠道对策，打通"体验引流 → 产地直邮"的产销闭环；
- **政府端**（新增乡村振兴运营洞察 Agent）：非遗活态传承指数、增收测算、濒危预警与工坊对策，全部指标可解释、可复现。

三端互为流量与数据闭环：游客行程带工坊体验与好物，工坊方案帮政府施策，政府看板反哺线路与资源调配。

### 1.2 目标用户

| 用户角色 | 核心诉求 | 对应功能 |
| --- | --- | --- |
| 普通游客 / 自由行人群 | 快速获得含非遗体验的可执行行程 | 旅行规划 Agent、美食民俗 Agent |
| 文旅爱好者 / 研学亲子 | 深入了解景点关联的非遗技艺与民俗 | 景点-非遗讲解 Agent、非遗知识库 Agent |
| 文旅宣传人员 / 文创从业者 | 低成本生成非遗故事与文创构思文案 | AIGC 文创生成 Agent |
| 非遗保护与传播机构 | 非遗资源数字化导览、活态传播 | 知识库 Agent（本地权威数据沉淀） |
| 乡村非遗工坊 / 传承人（新增） | 产品卖得掉、卖得好，体验客流变订单 | 乡村产业赋能 Agent |
| 文旅局 / 乡镇政府（新增） | 低成本量化评估非遗活态性与文旅增收 | 乡村振兴运营洞察 Agent |
| 地方工作人员（新增·v3.0） | 用自然语言问数、问对策，直接产出汇报材料 | 政务产业助手 Agent（智能对话体） |

### 1.3 功能需求

1. **用户交互**：结构化表单（目的地、天数、出行人群、是否优先非遗体验、线路模式）+ 自然语言对话双入口。
2. **智能行程生成**：输出每日行程，标注普通景点/非遗联动景点/乡村文旅点位，含区域、建议时长、餐饮安排；支持**城市经典 / 城乡融合 / 乡村深度**三种线路模式；城乡与乡村模式附加村宿建议与乡村好物推荐；支持一键重新生成。
3. **文旅-非遗联合讲解**：输入景点名，输出"① 景点历史 ② 关联非遗项目与民俗解读"两层内容，并提供口语化现场讲解稿。
4. **非遗知识库检索**：查询非遗项目类别、级别、传承人、技艺简介、体验点位与开放情况。
5. **AIGC 文创生成**：生成非遗趣味小故事、朋友圈宣传文案、文创产品构思三种内容。
6. **乡村产业赋能（新增）**：选择工坊后一键生成六件套方案——产品定位、三档定价建议（可解释公式）、电商详情页文案、30 秒短视频口播脚本、包装升级建议、渠道痛点对策与产销对接。
7. **乡村振兴运营看板（新增）**：非遗活态传承指数（HLI）排行、三档增收测算（参数可调）、濒危预警清单、工坊共性问题对策与结构图表。
8. **多智能体协作可视化（新增）**：智能对话页实时展示"调度器接收 → 意图识别 → Agent 分派 → 处理耗时 → 结果"协作链路（SSE 流式推送）。
9. **政务产业助手对话体（新增·v3.0）**：工作人员侧智能问答——总结归纳（直接产出汇报材料文本）、指标解读、濒危预警、工坊经营对策、跨城市对比；支持一键生成总结材料。
10. **看板地区下钻（新增·v3.0）**：乡村振兴看板支持城市与区县两级选择，指标、图表、预警、对策全部按所选口径重算；政务对话体复用同一口径。
11. **个人结果导出**：行程、讲解、推荐、答案、文创文案、赋能方案、看板数据、对话回答与归纳材料均支持一键复制导出。

### 1.4 非功能需求

| 维度 | 要求 | 落地方式 |
| --- | --- | --- |
| 可运行性 | 无大模型 API Key 也能完整演示 | LLM 为可选增强，失败自动降级为本地模板引擎 |
| 准确性（抑制幻觉） | 非遗事实性回答不得编造 | 知识库直答优先，LLM 仅在库内上下文约束下作答 |
| 可用性 | 公网可访问，不依赖校园内网 | 单端口 HTTP 服务，可部署于任意云主机/容器平台 |
| 性能 | 页面接口响应在秒级 | 知识库内存检索，仅生成类任务调用 LLM |
| 安全性 | 不泄露密钥与内部细节 | 密钥仅存环境变量；统一错误结构，不返回堆栈 |
| 可维护性 | 分层清晰、易扩展城市 | 控制器 / 服务 / 数据三层分离，新增城市只需追加数据文件 |

## 二、设计思路

### 2.1 总体架构

系统采用「前端网页 + API 网关 + 多智能体调度层 + 本地知识库」四层结构：

```
┌────────────────────────────────────────────────────────────┐
│  展现层  public/  (原生 HTML/CSS/JS 单页应用)              │
│  双身份工作台（顶栏一键切换）：                             │
│  · 旅行者视角：智能对话(协作链路可视化) | 行程规划 |        │
│    讲解 | 美食民俗 | 非遗知识库 | AIGC文创                  │
│  · 地方工作人员视角：乡村产业赋能 | 乡村振兴看板            │
│  · 两视角共用：个人中心（画像/资料、收藏夹按身份隔离）      │
└───────────────────────────┬────────────────────────────────┘
                            │ HTTP/JSON (REST) + SSE (协作链路流)
┌───────────────────────────▼────────────────────────────────┐
│  接口层  server/src/routes.js  (控制器，不含业务逻辑)       │
│  /api/cities /api/plan /api/guide /api/food                │
│  /api/heritage/* /api/aigc /api/chat                       │
│  /api/rural/* /api/insight /api/orchestrate/stream(SSE)    │
└───────────────────────────┬────────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────────┐
│  智能体调度层  agents/orchestrator.js  (原创意图路由)       │
│ ┌─────────┬─────────┬─────────┬──────────┬─────────┐       │
│ │ 旅行规划 │ 景点讲解 │ 美食民俗 │ 非遗知识库│ AIGC文创 │      │
│ │ planner │ guide   │ food    │ knowledge│ aigc    │       │
│ └─────────┴─────────┴─────────┴──────────┴─────────┘       │
│ ┌───────────────────────┬───────────────────────┐          │
│ │ 乡村产业赋能(工坊端)   │ 乡村振兴运营洞察(政府端) │         │
│ │ industry              │ insight               │          │
│ └───────────────────────┴───────────────────────┘          │
│  共享能力：llm.js（可选大模型增强，失败静默降级）           │
└───────────────────────────┬────────────────────────────────┘
```

### 2.2 关键设计决策

| 决策点 | 方案 | 理由 |
| --- | --- | --- |
| 项目结构 | 按功能组织 + 三层分离（控制器/智能体/数据） | 控制器不写业务逻辑，便于测试与扩展新城市 |
| 智能体协作 | 共享知识库 + 调度器路由，而非各 Agent 独立数据源 | 消解"旅游与非遗两张皮"，行程可与非遗深度绑定 |
| 大模型定位 | 可选增强层，非强依赖 | 保证比赛现场与公网部署在无 Key、断网时均可演示 |
| 幻觉治理 | 检索优先 + 上下文受限生成 + 来源标注 | 非遗属严肃文化内容，必须可溯源 |
| 前端技术 | 原生 HTML/CSS/JS，无构建步骤 | 部署零依赖，单端口即可运行，降低现场风险 |

### 2.3 核心创新点

1. **非遗与行程的深度绑定机制（原创）**：不是把"旅游"和"非遗"做成两个并列模块，而是在数据层建立「景点 ↔ 非遗」关联权重（`attractions[].heritageRefs`），规划 Agent 用"非遗关联数 ×10 + 人群类型偏好 + 非遗类点位加成"的原创评分函数对候选景点排序，非遗体验点会因关联度高而自动进入行程，并随出行人群（亲子/青年/老年）动态调整点位密度与游玩时长系数。
2. **三端闭环的产品架构（原创，v2.0 升级）**：游客端、工坊端、政府端共用同一套知识库与调度体系——游客行程为工坊导流（体验即消费），工坊赋能方案为政府施策提供素材，政府看板数据反哺线路与资源调配。非遗由此从"被保护对象"升级为"能造血的产业资产"，直接回应"乡村振兴""新时代产业赋能"命题。
3. **多智能体分工解耦 + 协作链路可观测**：八个 Agent 各司其职，调度器按意图与受众路由并串联应答；调度过程通过 SSE 流式推送，前端实时点亮"意图识别 → Agent 分派 → 处理耗时"协作链路，让"多智能体"从口号变成看得见的机制。
4. **面向非遗场景的幻觉抑制链**：命中知识库 → 按意图（地点/时间/传承人/级别）组卷直答；未命中 → 若有大模型则仅允许基于库内全量上下文作答，否则明确告知"暂未收录"并给出库内可答清单，杜绝编造非遗年代、传承人与名录级别。
5. **可解释的量化指标（原创，政府端核心）**：非遗活态传承指数（HLI）由"级别权重 + 传承人收录 + 体验点位 + 乡村产业联动"四个可审计维度构成；增收测算给出公式与三档情景，参数默认值取自知识库收录的工坊体验价与好物价中位数，用户可自行覆盖——所有指标拒绝黑盒随机数。
6. **AIGC 二次创作 + 可追溯标注**：文创内容由大模型在知识库事实约束下生成，输出结果自带"生成方式"标注（大模型生成 / 本地模板引擎生成），符合大赛对 AI 生成内容标注的要求。
7. **数据驱动的多城市扩展机制（原创，v3.0）**：城市注册（`cities.meta.js`：省份/古称/地标/区县别名）、地区归属（`regions.js`：区县列表 + 非遗归属区县映射）、统一注册中心（`registry.js`：城市校验、最长别名优先的城市识别、多城市识别用于对比问答、区县合法性校验、数据完整性审计）全部下沉数据层。新增城市只填 `heritage.js` / `rural.js` / `regions.js` / `cities.meta.js` 四张表——8 个 Agent、前端下拉、看板下钻、对话体、演示模式自动跟随；城市识别错误或未收录区县统一返回 400 并提示已收录清单，绝不静默兜底成默认城市。
8. **政务产业助手"问答 + 归纳"一体（原创，v3.0）**：工作人员对话体复用洞察 Agent 的 HLI 算法与知识库（不写第二份指标逻辑），意图识别覆盖总结/对比/风险/工坊/增收/指标七类；跨城市对比由别名识别自动触发；"一键生成总结材料"直接产出带标题、六分层小节、口径与数据来源声明的汇报文本，可整体复制。

## 三、功能模块设计（七大智能体）

### 3.1 旅行规划 Agent（planner.js）

- **输入**：目的地（cityId）、出行天数（1-7）、出行人群（family/youth/elder）、是否优先非遗体验、**线路模式**（city 城市经典 / blend 城乡融合 / rural 乡村深度）。
- **处理流程**：
  1. 按线路模式组装候选池：城市经典取城市景点池；乡村深度取乡村点位池（乡村振兴示范村、非遗工坊、农事体验）；城乡融合取两者并集；
  2. 按原创评分函数对点位排序：`score = 非遗关联数×10 + 人群偏好类型命中×5 + 非遗类点位×3 + 模式加权（乡村模式乡村点位+20 / 融合模式双向+8与+4）`；
  3. 按人群规则确定每日点位数（亲子 3、青年 4、老年 2，乡村模式封顶 3）与时长系数（1.3 / 1.0 / 1.5）；
  4. 按"上午 / 下午 / 傍晚夜游"时段组装每日行程，自动附加午晚餐推荐（含饮食非遗背景）；城乡与乡村模式附加**村宿建议**与**乡村好物推荐**；
  5. 调用大模型生成 50 字以内的行程总导语（失败则由本地模板生成）。
- **输出**：结构化行程 JSON，前端渲染为可复制的每日计划，含"非遗联动景点/乡村文旅点位"标签、关联非遗详情卡与亮点/最佳季节提示。

### 3.2 景点-非遗历史讲解 Agent（guide.js）

- **输入**：景点名称（支持模糊匹配，自动去除"景区/古城"等后缀）。
- **处理流程**：知识库检索 → 命中则输出"① 景点历史 ② 关联非遗项目与民俗（含级别、简介、体验点位）"；未命中则明确提示"本地知识库暂未收录，不作详细介绍"，可选用大模型给出通用说明并声明非知识库内容。
- **增强**：有 LLM 时基于知识库事实材料生成 150-250 字**口语化现场讲解稿**，提示词明确禁止引入材料外的新年代、人物与数字。

### 3.3 美食民俗推荐 Agent（food.js）

- **处理流程**：读取目的地美食库 → 标注必吃项（前 3 项）→ 为每道菜关联**饮食类非遗/民俗背景**说明 → 附加本地民俗活动清单（如泉州闽南拍胸舞、潮州大锣鼓与出花园）。
- **输出**：美食地图式结果，含"非遗/民俗背景"高亮区块。

### 3.4 非遗知识库 Agent（knowledge.js，核心）

- **数据**：非遗项目结构化条目——项目名、别名、类别、级别（人类非遗/国家级/省级）、技艺简介、代表性传承人、体验点位（名称/地址/开放情况）。
- **检索算法**：问题与项目名匹配（+10）、别名匹配（+8）、类别匹配（+3），得分 ≥8 判定命中。
- **意图识别**：通过词表识别 location / time / master / category / level 五类意图，按意图选择性组卷作答（例如只问体验地点时不会输出传承人信息）。
- **反幻觉策略**：命中直接组卷；未命中有 LLM 时限定"只能依据知识库内容回答，没有的信息一律回答本地知识库暂未收录"，无 LLM 时返回库内可答清单。
- **输出**：答案 + 来源标注（本地知识库直答 / 大模型+知识库上下文 / 未命中）+ 相关项目推荐。

### 3.5 AIGC 文创生成 Agent（aigc.js）

- **任务类型**：① 非遗趣味小故事（约 300 字）② 朋友圈宣传文案（约 180 字，含 emoji 与话题标签）③ 文创产品构思（3 个产品，含设计说明与文化寓意）。
- **处理流程**：选定城市 + 非遗项目 + 类型 → 拼接事实材料（项目简介、级别、体验点位）→ 大模型按任务提示词生成；无 LLM 时由**原创模板引擎**基于知识库事实产出，保证内容"有据可依"。
- **输出**：内容正文 + 生成方式标注，可一键复制。

### 3.6 乡村产业赋能 Agent（industry.js，新增·工坊端核心）

- **输入**：城市 + 非遗工坊（知识库收录 12 家工坊，覆盖德化白瓷、安溪铁观音、永春篾香/老醋、晋江面线、惠安石雕、潮绣、木雕、泥塑、单丛茶、通花瓷、竹编）。
- **六件套输出**：
  1. **产品定位**：主推款、核心/次级/潜力客群、非遗级别信任背书；
  2. **三档定价建议（可解释）**：以知识库收录的同类产品公开价格区间为市场锚，输出引流款（区间下限）/利润款（区间中位）/形象款（上限上浮10%）三档，并附毛利体检（毛利率 ≈ 1 − 成本占比，成本比例标注"行业通用参考"）；
  3. **电商详情页文案**：LLM 在知识库事实约束下生成（无 LLM 时模板引擎从卖点/产地故事/规格事实组卷）；
  4. **30 秒短视频口播脚本**：固定"钩子—工序—人物—引导"四段分镜；
  5. **包装升级建议**：信息层（非遗标识+产地+工序白话）/结构层（三档对应三包装）/体验层（工序明信片+体验券）/合规层（不承诺功效）；
  6. **渠道痛点对策 + 产销对接**：内置 12 条"痛点正则 → 处方"规则表，逐条应对工坊经营痛点；从乡村点位库反查同非遗点位，给出"体验引流 → 扫码下单产地直邮"闭环建议。
- **设计原则**：结构化建议（定位/定价/对策）全部由知识库字段 + 可解释规则计算，不依赖大模型；仅文案类内容交给 LLM（失败降级模板）。

### 3.7 乡村振兴运营洞察 Agent（insight.js，新增·政府端核心）

- **① 非遗活态传承指数（HLI，满分100，原创可解释算法）**：`总分 = 级别权重（人类非遗50/国家级40/省级30/其他20）+ 传承人收录（实名15/待核6/无0）+ 体验点位（每处10，封顶20）+ 乡村产业联动（有15/无0）`，按得分分为活力型（≥80）/稳健型（≥60）/观察型（≥40）/预警型（<40）。
- **② 三档增收测算**：`年收入 ≈ 游客量×体验参与率×体验客单价 + 游客量×好物转化率×好物客单价`；体验客单价默认取知识库工坊体验价格中位数均值，好物价取乡村好物价格区间中位；输出保守（×0.7）/基准（×1.0）/乐观（×1.6）三情景与带动就业估算，参数全部暴露、可由用户覆盖，并明示"情景推演工具，非统计数据"。
- **③ 濒危预警清单**：HLI 最低且低于观察线的项目，预警理由逐条列出（如"传承人待核实""无乡村产业联动"）。
- **④ 工坊共性问题对策**：聚类各工坊痛点，给出镇域层面统一组织建议。
- **⑤ 看板图表数据**：级别分布、类别分布、HLI 排行、工坊区县分布，前端以**零依赖 CSS 条形图**渲染（离线可用）。
- **公开统计数据**：知识库收录带来源的宏观指标（如凤凰单丛茶 2024 年一产产值 26.52 亿元、凤凰镇年接待游客超 800 万人次、全国乡村旅游重点镇等），每条标注来源与年份，供洞察结论引用。

### 3.8 政务产业助手 Agent（advisor.js，新增·工作人员端核心）

- **定位**：面向文旅局/乡镇工作人员的自然语言"问数 + 问策 + 归纳"入口；同一套 SSE 协作链路实现服务游客与工作人员（audience 区分）。
- **意图识别**（`detectIntent`，七类 + 兜底）：summary 总结归纳 / compare 地区对比 / risk 濒危与风险 / workshop 工坊经营 / revenue 增收测算 / metric 指标解读 / heritage 单项非遗 / overview 概况；问题中识别到 ≥2 个城市时强制进入 compare。
- **核心能力**：
  1. **总结归纳**：调用洞察 Agent 的 HLI 与统计口径，产出 6 个分层小节（总体情况/HLI 排行与薄弱项/增收测算/濒危预警/工坊共性与对策/下一步建议），建议按工作人员画像的"关注重点"（非遗工坊增收/非遗活化传播/乡村文旅客流）重排序；
  2. **地区对比**：`detectCities` 从问句识别多个城市，输出两侧非遗结构、HLI、乡村产业规模对照与差异化建议；
  3. **定向问答**：命中具体工坊给"六件套"摘要，命中指标给公式与口径解释，命中风险给预警清单与对策；
  4. **口径联动**：接收 cityId / county / focus 参数，回答口径与看板选择器一致；未收录区县返回 400。
- **反幻觉**：全部数字与名录信息来自知识库；未收录内容明示"暂未收录"，LLM 仅参与表达润色，不参与事实生成。

### 3.9 调度器（orchestrator.js）

- **城市识别**：完全数据驱动——调用 `registry.detectCity`（最长别名优先，含古称/地标/区县别名），新增城市无需改动本文件；问题中出现多个城市时用于对比路由。
- **受众路由**：tourist（默认）按规则表路由到 7 类游客智能体；**staff 一律交政务产业助手**，并透传 cityId / county / focus。
- **景点名优先识别**：遍历全部已收录城市景点名做包含匹配，命中且问句含"介绍/讲解/历史/怎么玩"时直接路由到讲解 Agent，并追加美食跟进提示（多 Agent 协同）。
- **规则路由**：按关键词表匹配七类意图（行业特定词"工坊/定价/增收/振兴"等**优先于**宽泛口语词"怎么样"等，避免误路由）；行程与文创类返回表单引导；未命中一律兜底走知识库 Agent。
- **意图分析纯函数化**：`analyze()` 独立暴露城市/景点/规则命中与目标 Agent，供 SSE 端点在调用前即时推送"意图识别"链路事件。

### 4.2 数据来源与治理原则

- **只收录可溯源的公开资料**：中国非物质文化遗产网（www.ihchina.cn）公布名录，以及福建、广东省非遗保护中心与泉州、潮州文旅部门公开资料，详见《非遗数据来源说明》。
- **不把事实性内容交给大模型生成**：非遗级别、名录年份、传承人、体验点位全部由团队人工整理入库；大模型仅参与表达润色与文创创作。
- **不确定信息显式标注**：传承人条目统一附"以中国非物质文化遗产网官方公布名录为准"；开放时间统一附"以现场公告为准"，避免误导。
- **扩展方式**：新增城市只需在 `data/heritage.js` 追加一个城市对象及其四类数据，无需改动任何 Agent 代码（体现了数据驱动的可扩展设计）。

## 七、安全性与可靠性设计

1. **配置集中与快速失败**：所有配置来自环境变量，启动时集中校验；密钥只存在于环境变量，代码库中仅保留 `.env.example` 占位值。
2. **统一错误体系**：类型化 AppError + 全局错误处理中间件，客户端只会收到 `{ok:false, code, message}`，绝不返回堆栈。
3. **结构化日志**：每行一条 JSON 日志，携带 requestId、方法、路径、状态码，不记录任何密钥与隐私数据。
4. **边界校验**：入参在路由层校验（如 cityId 必填、days 限制 1-7、type 限定枚举），不信任客户端数据。
5. **基础安全头**：`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: no-referrer`；JSON 请求体限制 100kb。
6. **外部依赖降级**：大模型调用设置超时（默认 30s），任何异常静默降级为本地模板，用户侧仍得到完整可用结果。
7. **优雅停机**：监听 SIGINT/SIGTERM，关闭 HTTP 服务后退出，最长等待 8 秒。

## 九、部署说明

1. 服务器安装 Node.js 18+；
2. 上传项目源码，进入 `server` 目录执行 `npm install --omit=dev`；
3. 复制 `.env.example` 为 `.env`，按需填写 LLM 配置与端口；
4. 执行 `npm start` 启动，服务默认监听 3000 端口，同时托管前端页面；
5. 使用 Nginx 反向代理 80/443 端口并配置 HTTPS 域名，即可实现公网访问（不使用校园内网）；
6. 可选：以 PM2 或 systemd 托管进程，实现开机自启与崩溃重拉。
